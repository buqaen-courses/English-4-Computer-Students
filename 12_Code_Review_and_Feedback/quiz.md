# Code Review Mastery Quiz

**Review Process and Mindset:**

1. **First-Time Reviewer Jitters:** You're reviewing your first pull request from a senior developer. You find a potential performance issue. How do you phrase your feedback to show respect while addressing the concern?

2. **Time-Pressured Reviews:** You have 15 minutes to review a 200-line code change before a deployment deadline. How do you prioritize your review focus and communicate any concerns?

3. **Biased Review Awareness:** You notice you're being more critical of code from a team member you've had disagreements with. How do you ensure your review remains objective and constructive?

**Communication and Feedback Patterns:**

4. **Harsh Feedback Rephrasing:** Transform this critical feedback into constructive language: "This code is full of bugs and will never work in production." Provide three different ways to rephrase it.

5. **Question-Based Feedback:** Instead of directly criticizing, reframe feedback about a poorly named variable using questions that encourage the author to think about naming conventions.

6. **Blocking vs. Suggestive Feedback:** Classify each type of feedback and explain when to use each: (a) "This security vulnerability must be fixed before merging," (b) "Consider using early returns to improve readability," (c) "Why did you choose this algorithm over the standard library implementation?"

**Context-Specific Review Scenarios:**

7. **Security Review Focus:** You're reviewing code that handles user passwords. What specific security concerns would you prioritize, and how would you communicate them?

8. **Performance Review Analysis:** A function processes large datasets but uses nested loops. How would you analyze and provide feedback on potential performance improvements?

9. **Accessibility Review Checklist:** When reviewing frontend code, what accessibility principles would you check for, and what specific feedback would you provide?

**Team Dynamics and Culture:**

10. **Mentorship Through Reviews:** How would you structure a code review for a junior developer differently than for a senior developer? What balance would you strike between education and efficiency?

11. **Conflicting Review Feedback:** Two reviewers provide contradictory suggestions on the same code. How do you facilitate resolution while maintaining team harmony?

12. **Review Load Management:** As a team lead, how do you distribute code review responsibilities to prevent burnout while ensuring quality?

**Tools and Workflow Integration:**

13. **PR Template Optimization:** Design a pull request template that guides authors toward better descriptions and helps reviewers understand changes more quickly.

14. **Automated Review Integration:** How do you combine automated tools (linters, tests, security scanners) with human review to maximize efficiency and coverage?

15. **Remote Review Challenges:** What strategies would you implement to make code reviews effective in a fully remote team?

**Advanced Review Techniques:**

16. **Architecture Review Process:** How would you review a major architectural change (like switching from monolith to microservices) through code review?

17. **Cross-System Impact Analysis:** When reviewing a change to a shared library, what broader impacts would you consider and communicate to stakeholders?

18. **Legacy Code Review Strategy:** How do you approach reviewing changes to a 10-year-old codebase with inconsistent patterns and no tests?

**Quality Assurance and Metrics:**

19. **Review Quality Measurement:** What metrics would you track to assess the effectiveness of your team's code review process? How would you use these metrics to drive improvements?

20. **Review Process Improvement:** Based on feedback from team members, how would you redesign your code review process to address common pain points?

**Ethical and Professional Considerations:**

21. **Bias Mitigation:** How do you ensure code reviews don't reflect unconscious biases related to gender, background, or coding style preferences?

22. **Feedback Delivery Ethics:** When you must deliver difficult feedback about serious code issues, how do you balance honesty with empathy?

**Real-World Application Scenarios:**

23. **Open-Source Review Dynamics:** How does reviewing code for an open-source project differ from reviewing code for a commercial product? What additional considerations apply?

24. **High-Stakes Review:** You're reviewing code for a critical financial system. How does the higher risk level change your review approach and communication?

**Career and Professional Development:**

25. **Review Skill Development:** What specific skills would you focus on developing to become a more effective code reviewer? How would you measure your progress?

**Bonus - Review Process Design:**

26. **Complete Review Workflow:** Design a comprehensive code review process for a 20-person development team, including roles, stages, tools, and quality gates.

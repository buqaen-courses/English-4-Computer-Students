# Open Source Mastery Quiz

**License Fundamentals:**

1. **License Selection Scenario:** You're creating a JavaScript utility library for data validation. Compare MIT vs. GPL licenses for this project. Which would you choose for maximum adoption, and what are the trade-offs?

2. **Dependency License Conflict:** Your project uses an MIT-licensed library and a GPL-licensed library. Can you distribute your combined project? Explain the compatibility issues and potential solutions.

3. **Commercial Integration:** A company wants to integrate your GPL-licensed open source project into their proprietary software. What options do they have, and what are the implications?

**Contribution Process:**

4. **First Contribution Setup:** Walk through the complete setup process for contributing to a GitHub repository, including forking, cloning, branching, and creating a pull request.

5. **PR Description Craft:** You're submitting a bug fix for a memory leak in a popular library. Write a complete pull request description that would convince maintainers to merge your change.

6. **Code Review Response:** A maintainer requests changes to your PR, asking for additional error handling. Write a professional response explaining your implementation and any follow-up changes.

**Project Management:**

7. **Issue Triage:** As a project maintainer, you receive these issues: (a) "App crashes on startup," (b) "Add dark mode support," (c) "Improve documentation." How would you prioritize and categorize them?

8. **Release Planning:** Your project has accumulated several bug fixes and features. How would you decide what goes into the next release using semantic versioning principles?

9. **Community Management:** A new contributor submits low-quality code with poor commit messages. How do you provide constructive feedback while encouraging continued participation?

**Legal and Ethical Considerations:**

10. **Contributor License Agreement:** Explain why some projects require CLAs and how they differ from standard open source licenses. What are the implications for contributors?

11. **Security Vulnerability:** You discover a security flaw in a library you maintain. Outline the responsible disclosure process and communication strategy.

12. **Dual Licensing:** Some projects offer both open source and commercial licenses. Explain this model, its benefits for maintainers, and implications for users.

**Advanced Scenarios:**

13. **Fork Management:** A contributor creates a fork of your project and adds significant features. How do you handle merging these changes while maintaining project quality and direction?

14. **Dependency Management:** Your project depends on a library with a known security vulnerability. How do you handle updating dependencies while minimizing disruption to users?

15. **Monetization Strategy:** You're maintaining a popular open source tool. Explore different monetization approaches (donations, sponsorships, dual licensing) and their impact on the community.

**Career and Professional Development:**

16. **Portfolio Building:** How would you strategically build an open source portfolio to appeal to different types of employers (startups vs. enterprises vs. research institutions)?

17. **Collaboration Skills:** What non-technical skills does open source contribution help develop, and how do they transfer to professional software development roles?

18. **Industry Networking:** How can open source participation lead to professional opportunities like conferences, speaking engagements, and job offers?

**Community and Culture:**

19. **Inclusive Community Building:** Design a code of conduct and contribution guidelines for a new open source project that promotes diversity and inclusion.

20. **Conflict Resolution:** Two core contributors disagree on a major architectural decision. How do you facilitate resolution while maintaining project momentum?

**Real-World Application:**

21. **Project Launch:** You're launching a new open source data science library. Outline your first 30 days plan, including setup, community building, and initial feature development.

22. **Legacy Project Adoption:** You want to contribute to a large, established project with complex contribution processes. How do you approach getting started and making meaningful contributions?

**Global and Cultural Aspects:**

23. **International Collaboration:** Your project attracts contributors from different time zones and cultures. What strategies would you implement for effective global collaboration?

24. **Localization:** How would you approach translating project documentation and supporting non-English contributors while maintaining consistency?

**Future Trends:**

25. **AI-Assisted Development:** How might AI tools change open source contribution workflows? What new opportunities and challenges would they create?

**Bonus - Comprehensive Planning:**

26. **Open Source Business Model:** Design a sustainable business model for an open source company that balances community needs with financial viability. Include revenue streams, community engagement, and governance structures.

27. **Personal Contribution Strategy:** Create a 6-month plan for building your open source presence, including project selection, contribution types, skill development, and community engagement goals.

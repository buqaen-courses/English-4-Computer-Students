# Technical Writing Mastery Quiz

**Documentation Design Scenarios:**

1. **The Open-Source Project:** You're launching an open-source library on GitHub. What sections must your README include, and how would you structure them to serve different reader personas (executive, developer, end user, contributor)?

2. **The API Documentation Dilemma:** Your team has built a REST API, but developers are struggling to integrate it. What three types of documentation would you create, and what would each focus on?

3. **The Legacy Code Handover:** You're leaving a project and need to document a complex algorithm for your successor. How would you structure this documentation to help them understand both the "what" and the "why"?

**Error Communication Challenges:**

4. **The Cryptic Error:** Your application shows users "Error 500: Internal Server Error." How would you redesign this error message to be more helpful, and what information would you include?

5. **The Configuration Failure:** A user gets "Invalid configuration file" when setting up your software. What steps would you take to make this error message actionable and prevent future occurrences?

**Code Documentation Scenarios:**

6. **The Complex Algorithm:** You wrote a sorting algorithm with multiple optimization strategies. What comments would you write to explain the trade-offs and why certain approaches were chosen?

7. **The API Function:** You're documenting a function that uploads files to cloud storage. What information should the documentation include about parameters, return values, and potential errors?

**Content Strategy Decisions:**

8. **The Multi-Audience Challenge:** You're writing installation instructions for a data science tool used by both beginners and experts. How would you structure the content to serve both audiences without overwhelming either?

9. **The Troubleshooting Guide:** Users frequently encounter the same three issues with your software. How would you organize a troubleshooting section that's easy to scan and search?

**Quality and Process:**

10. **The Documentation Review:** You're reviewing a colleague's API documentation. What criteria would you use to evaluate its quality and completeness?

**Real-World Application:**

11. **The Product Launch:** Your startup is about to launch a SaaS product. What documentation would you prioritize creating first, and how would you ensure it's accessible to different user types?

12. **The International Expansion:** Your documentation currently assumes English-speaking technical users. What changes would you make to support a global, multilingual audience?

**Bonus - Writing Process:**

13. **The Documentation Workflow:** Describe a systematic process for creating technical documentation, from planning to publication, incorporating tools and review steps mentioned in the article.
